2. Descripción General del Proyecto

¿Qué es Sistema Biométrico?

Sistema Biométrico es una aplicación web completa para la gestión de asistencia de empleados en instituciones educativas y empresariales. Integra biometría (huella dactilar y reconocimiento facial) con normas laborales mexicanas (AEFCM) para:

  • Registrar entrada/salida de empleados
  • Calcular retardos automáticamente
  • Gestionar sanciones y justificaciones
  • Administrar comisiones de trabajo
  • Generar reportes detallados
  • Controlar múltiples dispositivos biométricos

Contexto de Negocio

El sistema está diseñado para instituciones educativas (AEFCM) con múltiples sedes/departamentos. Soporta hasta 35 dispositivos biométricos diferentes, permite gestionar comisiones de trabajo, y mantiene un registro de auditoría completo para cumplimiento normativo.

Tecnología

  • Backend: PHP 7.4+
  • Base de Datos: MySQL 5.7+
  • Frontend: Bootstrap 5, JavaScript vanilla
  • Testing: PHPUnit 9.x
  • Seguridad: AES-256-CBC, CSRF tokens, Password hashing

6. Seguridad e Implementaciones

Autenticación

2FA (Autenticación de Dos Factores)

Implementado en AuthController::verify2FA(). Genera código de 6 dígitos válido por 300 segundos, con máximo 5 intentos fallidos.

Encriptación

        AES-256-CBC (helpers/Encryption.php)
        
        - Clave: ENCRYPTION_KEY (desde .env)
        - IV: Aleatorio por cada operación
        - Datos encriptados: datos biométricos, fotos
        
        Uso:
        $encrypted = Encryption::encrypt($datos);
        $decrypted = Encryption::decrypt($encrypted);

Prevención de Ataques

Vulnerabilidad Técnica de Prevención Implementación
CSRF (Cross-Site Request Forgery) CSRF Tokens helpers/Csrf.php - Tokens en formularios
SQL Injection Prepared Statements Todos los queries usan ? placeholders
XSS (Cross-Site Scripting) htmlspecialchars(), htmlentities() Todos los datos de usuario escapados en vistas
Fuerza Bruta Rate limiting (implícito en 2FA) Máximo 5 intentos 2FA en 5 minutos
Acceso No Autorizado Control de Permisos SoporteController::checkAccess() + validaciones

Control de Acceso (RBAC)

  • admin: Acceso total a todas las funcionalidades
  • usuario: Acceso a su propio registro y funcionalidades básicas
  • gerente: Acceso a reportes y aprobaciones

Auditoría

  • Tabla sanciones con campos modified_by y fecha_modificacion
  • Tabla logs_dispositivos para registrar todas las verificaciones biométricas
  • Timestamps en todas las tablas principales
  • Query logs en logs/ para debugging

7. Flujos de Negocio

7.1. Flujo de Entrada de Empleado

        1. Empleado escanea huella/cara en dispositivo CKTeco
        2. DispositivoBiometrico recibe datos
        3. BiometricosController::registrarHuella() procesa
        4. AsistenciaService::registrarEntrada() valida:
           ✓ Empleado activo
           ✓ Datos biométricos válidos
           ✓ Horario laboral
        5. Asistencia::registrarEntrada() crea registro
        6. Retardo::calcularRetardo() calcula si hay atraso
        7. Si retardo ≥ 10 min: crea registro retardo
        8. Si 5 retardos: Sancion::create() con tipo 'suspension'
        9. LogDispositivo registra el evento
        10. Dashboard muestra actualizado

7.2. Flujo de Comisión (Normas AEFCM)

        1. Gerente crea comisión (ComisionController::create())
        2. Comision::create() valida según AEFCM:
           ✓ Tipo válido (viaticos, gastos, etc.)
           ✓ Monto ≤ $3,000 mensual
           ✓ Días ≤ límite por tipo
        3. Si requiere_aprobacion: estado = pendiente
        4. Admin/Gerente aprueba (ComisionController::aprobar())
        5. Comision::justificar() marca como justificada
        6. Reporte genera con comisiones aprobadas

7.3. Flujo de Justificación de Retardo

        1. Empleado solicita justificación (JustificacionController::justificar())
        2. Selecciona tipo: Enfermedad, Tráfico, Otro, etc.
        3. Adjunta documento de soporte
        4. SoporteController verifica acceso y almacena archivo
        5. Admin/Gerente revisa justificación
        6. Si aprobada: Retardo::actualizar() con estado justificado
        7. Ya no cuenta para suspensión automática

10. Guía de Despliegue

Prerrequisitos

  • PHP 7.4+ con extensiones: PDO, OpenSSL, JSON
  • MySQL 5.7+ o MariaDB 10.3+
  • Apache/Nginx con mod_rewrite
  • Composer (para gestión de dependencias)
  • Git (para versionado)

Paso 1: Clonar y Configurar

# Clonar repositorio
git clone https://repo.example.com/sistema-biometrico.git
cd sistema-biometrico

# Copiar archivo de configuración
cp config.example.php config.php

# Editar credenciales
nano config.php
# Establecer:
# - DB_HOST, DB_USER, DB_PASS, DB_NAME
# - ENCRYPTION_KEY (generar con: openssl rand -base64 32)
# - BASE_URL

Paso 2: Base de Datos

# Crear base de datos
mysql -u root -p < database.sql

# Ejecutar migraciones (en orden)
mysql -u user -p database < migrations/20251119_add_sanciones_retardos_soporte.sql
mysql -u user -p database < migrations/20251126_add_dispositivos_biometricos_config.sql
mysql -u user -p database < migrations/20251127_add_sanciones_modificacion_audit.sql

Paso 3: Permisos y Directorios

# Crear directorios necesarios
mkdir -p uploads/fotos_empleados
mkdir -p uploads/justificaciones
mkdir -p logs

# Permisos
chmod 755 uploads/
chmod 755 logs/
chown www-data:www-data uploads/ logs/

Paso 4: Configuración Web

# Apache (.htaccess)
RewriteEngine On
RewriteBase /sistema_biometrico/
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^(.*)$ index.php [L]

Paso 5: Testing

# Ejecutar tests
./vendor/bin/phpunit tests/Unit/

# Ejecutar todos los tests
./vendor/bin/phpunit

# Con cobertura (requiere coverage)
./vendor/bin/phpunit --coverage-html=coverage/

Paso 6: Primer Usuario Admin

# Acceder a /register (como admin)
Usuario: admin
Contraseña: (generar segura)
Rol: admin

11. Problemas Conocidos y Recomendaciones

⚠️ Problemas Críticos

Cobertura de tests muy baja (10%). Necesita aumentar a 50%+ antes de producción
Sin manejo de errores en BiometricosController (conexión a CKTeco)
Performance no optimizada (sin índices en queries complejas)
Sin rate limiting en login (solo 2FA)
Sin SSL/TLS en configuración (recomendado para biometría)

⚠️ Problemas Moderados

Validación de entrada incompleta en algunos controllers
Sin manejo de transacciones fallidas
Logs de auditoría muy simples
Sin backup automático de base de datos

✅ Recomendaciones

Corto Plazo (1-2 semanas)
  • Aumentar cobertura de tests a 30%+ (agregar más tests en Unit/Functional)
  • Implementar rate limiting en login
  • Agregar validación completa de inputs
  • Documentar endpoints de API con Swagger
  • Configurar SSL/TLS
Mediano Plazo (1-2 meses)
  • Aumentar cobertura a 60%+
  • Implementar cache (Redis/Memcached)
  • Optimizar queries lentas
  • Agregar alertas y notificaciones por email
  • Implementar backup automático
Largo Plazo (2-3 meses+)
  • Migrar a framework moderno (Laravel, Symfony)
  • Implementar API REST completa con OAuth
  • Agregar soporte para múltiples idiomas
  • Crear aplicación móvil (iOS/Android)
  • Implementar analytics y business intelligence
